# 🌌 Treehole 赛博树洞 - 项目设计与开发报告

## 一、 项目介绍

### 1.1 项目简介
在数字化生存的今天，社交媒体的繁荣反而加剧了人类的“赛博孤独”。用户在朋友圈、微博等实名或半实名平台上，往往受困于“社交压力”和“人设维护”，难以表达最真实的自我。**Treehole 赛博树洞** 旨在打造一个纯粹的、充满赛博朋克美学色彩的匿名情感交互空间。

本项目不仅是一个简单的留言板，它融合了 **深色极简主义 (Dark Minimalism)** 与 **毛玻璃美学 (Glassmorphism)**。核心设计哲学是“去中心化身份”，用户无需注册，仅凭本地生成的 UUID 即可参与互动。通过“漂流瓶”这一经典的异步社交载体，我们将这种孤独感转化为一种“跨越海洋的相遇”。更重要的是，项目引入了 **Alter Ego (Danganronpa Theme)** 智能体，它不只是一个聊天机器人，更是系统中的一个“观察者”和“守望者”，通过数据分析和希望注入（Hope Injection）算法，为匿名者的负面情绪提供实时的、带有仪式感的慰藉。

从技术层面看，Treehole 是一个典型的高可用全栈应用。后端基于 Spring Boot 3 + Java 17 构建，持久层采用 MyBatis-Plus 简化开发，利用 WebSocket 实现实时回响通知。前端则深度运用 Vue 3 组合式 API 与 Vite 构建引擎，并集成了三维力导向图 (3D Force Graph) 来视觉化展现复杂的心灵链接。为了应对现代网络环境的不稳定性，我们还设计了“离线胶囊”机制，确保用户在断网时也能保留那份珍贵的心绪。

### 1.2 项目模块与功能 (CRUD 完整性)
1.  **匿名留言模块**：核心 CRUD 闭环。支持发布留言、点赞、动态表情回复及删除。
2.  **虚灵之海 (漂流瓶)**：实现复杂的异步状态管理。包括投掷（Create）、捞取（Read/Update）、回复（Update）及归还（Delete 逻辑转化）。
3.  **Alter Ego 智能体**：基于 LLM 的 AI 交互。支持实时对话分析，针对留言关键词生成带有角色扮演色彩的回复。
4.  **回响中心**：基于 WebSocket 的实时消息中心，当留言或瓶子获得互动时，实时推送通知。
5.  **能量商店**：基于能量经济系统的 CRUD 练习。用户通过互动获取能量，兑换（Purchase）并装备（Update）视觉特效。

### 1.3 同类型产品简介
*   **贴吧/微博**：重度社交，存在严重的社交压力和信息噪音。
*   **一罐**：早期的匿名社交尝试，侧重于情绪分类，但在视觉沉浸感和 AI 互动深度上略显不足。
*   **Soul**：虽然主打灵魂社交，但目前已高度商业化，匹配机制复杂。

## 二. 项目建模

### 2.1 数据库建模 EER 图
详见 [数据库参考手册](database_reference.md)。
*   **实体**：USER (用户), MESSAGE (留言), COMMENT (评论), TAG (标签), DRIFT_BOTTLE (漂流瓶)。
*   **关联**：1:N (用户发布留言), N:M (留言与标签关联), 1:N (留言包含评论)。

### 2.2 项目应用建模
*   **逻辑层级**：Controller (接口层) -> Service (业务逻辑层) -> Mapper (持久化层) -> Entity (实体模型)。
*   **技术架构**：
    *   前端：Vue 3 + Vite + Tailwind CSS (美学呈现)
    *   后端：Spring Boot 3 + WebSocket (核心逻辑)
    *   中间件：MySQL 8.0 (数据存储) + Zhipu AI (情感引擎)

## 三. 项目落地

### 3.1 数据库设计
*   **实体表**：详细字段定义参见 `sql/01_init.sql`。
*   **特色设计**：使用了 JSON 类型存储 `reactions` 统计，通过 `ON UPDATE` 自动维护 `update_time` 审计字段。

### 3.2 项目架构
*   **模块化分包**：
    *   `com.treehole.controller`: RESTful API 暴露。
    *   `com.treehole.service`: 核心算法，如漂流瓶捞取逻辑、AI 提示词工程。
    *   `com.treehole.websocket`: 推送服务。
*   **CRUD 完整性**：所有业务逻辑均通过统一的 `Result` 对象返回，并配有 `GlobalExceptionHandler` 进行异常兜底。

### 3.3 云服务部署
*   **基础设施**：本项目已完成 **Docker 化改造**。
*   **部署情况**：通过 `compose.yml` 实现一键编排。已在本地 WSL 2 模拟云环境环境下测试通过，支持 Nginx 反向代理。

## 四. AI 使用情况

### 4.1 AI 工具使用阐述
1.  **Antigravity (Coding Assistant)**：用于项目代码架构搭建、复杂 SQL 优化以及前端毛玻璃样式的精细调整。
2.  **智谱 AI / GLM-4**：作为项目内置的 AI 引擎，负责生成 Alter Ego 的对话内容。

### 4.2 借助 AI 选学后续章节
*   **选学内容**：分布式 WebSocket 会话管理（针对多机房部署的场景）。
*   **情况说明**：通过 AI 学习了如何利用 Redis Pub/Sub 来同步不同节点的 WebSocket 消息，解决了集群环境下推送失效的痛点。
